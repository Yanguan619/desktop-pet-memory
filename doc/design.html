精简版记忆架构：判断权分配 + 五层记忆 + 三线管道

本版重写的核心不是"多加几个模型"，而是把每个判断交给唯一最合适的执行者，并且禁止任何执行者用"省钱"的理由做价值判断。上一版的设计缺陷都来自同一个根源：用长度、字数这类廉价启发式冒充语义判断，于是"省一次模型调用"变成了"静默丢一条记忆"。

三条线的入口都只有工作记忆。用户的一句查询首先是对话的一轮，然后才触发召回；召回结果只注入本轮回复上下文，不写回工作记忆——否则会被当成对话内容再编码一遍。

一、判断权分配（本版核心）

表里每一行是一个必须回答的问题。没有"兜底规则"这一列，因为兜底只能是把问题交给下一层更强的判断者，或者标记为未知并保留原始事实，不允许猜。

判断执行者参数执行者不可用时
本轮有没有值得记的信息？属于哪层？摘要是什么？ system2：qwen3.5:0.8b，JSON Schema 强约束，逐轮调用 temperature=0、think=false、num_predict=256、prompt 带一个 few-shot 示例 这一轮不写入记忆（像发烧时记不住事），并把错误交回调用方，由宿主决定是否提示用户
新记忆与已有记忆的关系：补充 / 更新 / 矛盾 / 无关 两段式：embedding 粗筛（余弦过阈值，取 top3；不按层级过滤）→ 命中才让 system2 判关系 粗筛只负责"值得问一下"，语义裁决只在命中时花一次调用 粗筛不可用 → 不做合并，两条都留（宁可重复，不可覆盖）
两条文本有多相似？（召回、聚类） embedding：qwen3-embedding:0.6b，1024 维，L2 归一化后取余弦 阈值必须按模型标定，见第九节 退化为标签精确匹配 + 强度排序，不假装有相似度
这条记忆有多重要？ 规则：显式记忆请求、层级、实体数、是否重复（只加分） 见第六节；只决定排序与复习节奏，不决定存不存 —
什么时候忘？强度怎么变？ 数学：艾宾浩斯 8 档间隔 + 指数衰减；自变量是经历轮次（tick），不读墙钟 见第七、八节 —
现在编码，还是延后批量编码？（只影响时机，不影响存不存） system1：qwen3:0.6b 二分类，约 150ms；仅在同步首字延迟被实测卡住时启用 回答错也只会让编码早/晚几秒 一律进异步队列
身份层提炼（"这个人稳定是什么样"） system2：反思时按簇调用，输入是簇内成员列表，输出一条规范表述 需要 ≥ 3 条独立证据才触发 保持原状，下次反思再试
这条内容要不要丢弃？ 没有人有权丢弃 遗忘只有一个出口：衰减到 archived，语义是压缩（细节变淡、排序打折、仍可召回），记录永久保留 —

四条铁律（违反任意一条都会重现上一版的缺陷）：

  • 规则只准省钱，不准判价值。规则可以决定"跳过模型"，但只能跳过闭集内的确定对象（例如与工作记忆完全相同的重复轮次），不能用长度、字数、标点这类代理指标。
  • 判价值的只能是 system2。它说没价值，那是"这轮不产生新记忆"，不是"丢弃原文"。
  • 嵌入只负责相似度，不负责结论。相似 ≠ 同一件事，所以合并永远需要 system2 仲裁。
  • system1 只准决定时机。它回答"现在处理还是稍后处理"，永远不回答"存不存"。

二、记忆分层与对象

层级作用典型内容
工作记忆当前会话缓冲区，三条线唯一入口最近 8 轮原始对话（用户输入、查询、宠物回复）
情景 episodic事件级记录某次对话发生了什么、任务状态
语义 semantic事实与偏好用户习惯、项目约束、实体关系
程序 procedural能力与流程工作流、工具策略、可复用步骤
身份 identity稳定自我模型长期目标、风险偏好、安全边界
class Memory:
    id: str
    layer: str                # "episodic" | "semantic" | "procedural" | "identity"
    content: str
    importance: float         # 0~1，写入时由规则确定，只影响排序与复习节奏
    strength: float           # 0~1，复习上升、按「经历轮次」衰减（不是按日历天）
    review_count: int
    created_tick: int         # 创建时的逻辑时钟
    last_review_tick: int     # 上次被召回/复习时的逻辑时钟
    next_review_tick: int     # 下次该结算的 tick（反思线据此挑目标）
    decayed_tick: int         # 上次结算衰减用的 tick：保证同一段时间不会被重复扣
    created_at: datetime      # 宿主传进来的展示时间戳（Event.at），本库从不读墙钟
    source_event_id: str
    tags: list[str]
    status: str               # "active"（清晰）| "fading"（细节变淡）| "archived"（压成索引，仍可召回）

    # 以下为本版新增，保证"判断可追溯、历史可回滚"
    embedding: bytes          # float32[1024] 打包，embedding 模型不可用时为 NULL
    embedding_model: str      # 例如 "qwen3-embedding:0.6b"，换模型后据此重算
    supersedes: str | None    # 被本条取代的旧记忆 id（矛盾/更新时产生，旧记录转 archived，原文保留）
    confidence: float         # system2 自评，用于排查模型抖动，不参与丢弃
    due_at: str | None        # 提醒：内容里说的那一刻（YYYY-MM-DD HH:MM，本地时间），不是生命周期
    notified: bool            # 提醒是否已交付给宿主，避免同一个提醒反复响

content 一经写入永不被覆写。更新只能产生新记录并带上 supersedes，旧记录转 archived——这条规则让"记忆被改写成别的意思"从可能变成不可能。

逻辑时钟：遗忘由经历驱动，不看日历

强度不是时间（wall clock）的函数，而是经历次数的函数。全局维护一个单调递增的整数 tick，与记忆同库存持久化（meta 表），每有一轮对话进入工作记忆就 +1。记忆只记录自己在第几 tick 出生、第几 tick 被复习，衰减按"经历了多少轮"结算：

# 曲线形状沿用艾宾浩斯：指数衰减 + 强度越结实衰减越慢；自变量从「天」换成「经历轮次」
def apply_decay(mem: Memory, tick: int) -> None:
    if mem.status == "archived":
        return
    delta = tick - mem.decayed_tick              # 距上次结算经历了多少轮，不是过了多少天
    rate = 0.02 / (1 + mem.strength * 2 + mem.importance * 3)   # 越结实越难忘
    decay = 1 - exp(-rate * delta / DECAY_SCALE)                # DECAY_SCALE ≈ 20 轮（需标定）
    mem.strength = max(0.0, mem.strength - decay * mem.strength)
    mem.decayed_tick = tick                      # 增量结算：同一 tick 反复算也不会多扣

    if mem.strength < 0.05 and mem.review_count == 0:
        mem.status = "archived"
    elif mem.strength < 0.08:
        mem.status = "fading"

def freshness(mem: Memory, tick: int) -> float:
    """新鲜度同样只看经历轮次，不看日期。"""
    return exp(-(tick - mem.last_review_tick) / FRESH_SCALE)      # FRESH_SCALE ≈ 8 轮（需标定）

换掉墙钟带来四个直接后果，都是想要的：

  • 关机不遗忘。宠物关掉一个月再打开，tick 一步没动，所有记忆强度原样——对它来说这一个月什么都没发生。
  • 时钟不再可信也不影响正确性。改系统时间、跨时区、夏令时、机器休眠、笔记本合盖，全部与记忆机制无关，因为没有任何计算读墙钟。
  • 可复现。同一条对话序列永远得到同一个记忆状态；测试只要把 tick 推到第 N 轮，不需要注入时钟。
  • 结算次数无关。衰减按「距上次结算」增量结算并记录 decayed_tick，所以每轮结算一次和攒 100 轮结算一次结果相同。早期版本用 tick - last_review_tick 且不回写，同一段时间被反复扣——实测 116 轮就归档，修好后是 6594 轮。"用得越勤忘得越快"这种反直觉行为就是这么来的。

遗忘是压缩，不是消失

这里的宠物不是人脑：存储够用，就不该真的缺东西。衰减只做三件事：降低清晰度（active → fading → archived 三个档位就是压缩程度）、降低召回排序权重（压缩态打 0.5 折）、压低细节的可读性。它不做的是：把记忆从库里抹掉、或者让它不可召回。

  • 强度有地板（STRENGTH_FLOOR = 0.03）：压到底也保留最小可召回权重，永远不会归零。
  • 召回范围是全部记忆，归档记录照常参与打分，只是排在清晰记忆之后。
  • 被想起就重新变清晰（update_strength_on_recall 会把 status 拉回 active）——这就是"旧事重提，细节又回来了"。
  • 所以长期闲置的代价是"想起来要多问一句"，不是"想不起来"。

库里不存任何墙钟时间（created_at 已删除）：宿主若要显示"三天前说过"，按记忆 ID 自己记时间。

时间事实：提醒

"2026-11-15 提醒我买蛋糕"里的 11-15 不是记忆的年龄，而是事实本身，所以它存在内容侧（due_at），与生命周期（tick）完全分开：

  • 换算由代码做，不交给模型。实测 0.8b 会把示例里的日期照抄、把「下周三」算成明天。确定性解析（memory/dateparse.go）覆盖：YYYY-MM-DD、今天/明天/明天晚上/后天/大后天、N 天后、N 周后、N 个月后、下下周三、下周X / 这周X / 周X、下个月 N 号、月底、M月D日（今年已过则明年），中文数字（两/十五/三十五）同样支持。
  • 到期时间精确到分钟：due_at 是 YYYY-MM-DD HH:MM（本地时间）。时刻支持 15:30、下午3点、下午3点半、晚上8点、凌晨2点、中午12点；只说日期不说时刻时默认 09:00；只说"几点"不提日期时，取最近一次到来的那个时刻（今天已过则明天）。
  • 三级兜底，保证不丢也不猜：①代码解析 → ②模型给的绝对日期（校验格式 + 必须落在今天～5 年内）→ ③都失败则标 pending_due，由宿主回问「哪天？」，用户补上后 ConfirmDue 落库。绝不写一个猜出来的日期。
  • 库不读墙钟，提醒由宿主触发。DueReminders(now) 返回该响的提醒并标记 notified；同一提醒只响一次。递送方式（气泡、通知）是宿主的事。
  • 提醒不参与衰减压缩。到期前、以及日期还没补齐时，都不该因为"几周没人提"就沉下去。
  • 过期处理（方案 c）：过了 due_at 且已经交付过的提醒，反思时归档——原文保留、仍可召回；没交付过的过期提醒不归档，否则宿主关机期间就是静默丢失。
  • 相对时间必须有锚点：Event.At 由宿主传入，只用于把"明天/下周三"换算成绝对日期；它不是记忆的时间戳。

三、唯一 system2 调用点：逐轮抽取

只用一次模型调用回答三件事：值不值得记、属于哪层、怎么表述。它不做合并、不做打分、不做丢弃决定。

SCHEMA = {
  "type": "object",
  "properties": {
    "worth":      {"type": "boolean"},                    # 本轮是否产生新记忆
    "layer":      {"enum": ["episodic", "semantic", "procedural", "identity"]},
    "summary":    {"type": "string"},                     # 一句话，主语用「用户」
    "tags":       {"type": "array", "items": {"type": "string"}},
    "entities":   {"type": "array", "items": {"type": "string"}},
    "confidence": {"type": "number"},                     # 0~1 自评
  },
  "required": ["worth", "layer", "summary", "tags", "entities", "confidence"],
}

def encode_with_small_model(turn: str) -> tuple[dict | None, Exception | None]:
    """逐轮调用，只看本轮原文。

    请求参数（三个都是必须的，缺一个就会静默退化）：
      think  = false         # qwen3.5 默认开思维链，会烧光 num_predict 只产出 thinking
      format = SCHEMA        # 结构化输出，字段与类型由语法强制，不靠叮嘱
      options = {temperature: 0, num_predict: 256}
    prompt 里必须有一个 few-shot 示例：0.8b 对纯规则式 prompt 会输出空 summary。
    """

def encode_memory(turn: str) -> list[Memory]:
    extracted, err = encode_with_small_model(turn)
    if err is not None:
        # 模型不可用就不产生长期记忆——像发烧时记不住事。原文仍留在工作记忆里（几轮后被挤出），
        # 但它不会变成可召回的记忆；怎么提示用户由宿主应用决定。
        raise err

    # 模型判定本轮没有新的长期信息：不产生记忆，工作记忆里原文仍在。
    if not extracted["worth"]:
        return []

    mem = Memory(
        layer=extracted["layer"],
        content=extracted["summary"],
        importance=score_importance(turn, extracted),
        strength=0.3,
        review_count=0,
        created_tick=clock.tick,
        last_review_tick=clock.tick,
        next_review_tick=clock.tick + REVIEW_INTERVALS[0],   # 8 档，单位是轮次
        created_at=event.at,                                 # 宿主提供的展示时间戳
        source_event_id=event_id,
        tags=extracted["tags"],
        status="active",
        embedding=embed(extracted["summary"]),
        confidence=extracted["confidence"],
    )
    resolve_relation(mem)      # 第五节：embedding 粗筛 → system2 仲裁
    store.save(mem)
    return [mem]

编码线只吃本轮原文，不喂上下文。早期版本把整段工作记忆喂进去，0.8b 分不清本轮与上文，每轮都把上文重新摘要一遍，同一件事存出四条变体；指代消解交给召回线（它本来就拿整段工作记忆找线索），编码线不需要上下文。

四、失败与遗忘：模型不可用就不产生长期记忆

flowchart TD
    T["本轮原文"] --> M{"system2 可用？"}
    M -->|"否"| NOMEM["不产生长期记忆<br/>原文只留在工作记忆<br/>错误交回宿主应用"]
    M -->|"是"| W{"worth？"}
    W -->|"否（本轮无新信息）"| SKIP["不产生记忆<br/>原文仍在工作记忆"]
    W -->|"是"| NEW["按 schema 落库（active, strength=0.3）"]
    NEW --> FORGET["唯一的遗忘出口：衰减 → fading → archived<br/>归档记录不删除，可追溯"]
情形返回值落库用户可见后果
模型判定无新信息(nil, nil)不产生长期记忆无（原文仍在工作记忆，几轮后挤出）
模型不可用 / 超时 / 解析失败(nil, err)不产生长期记忆这一轮没记住，由宿主应用决定是否提示；原文只留在工作记忆里，不会变成可召回的记忆
embedding 不可用—记忆照写，embedding=NULL召回退化为强度/标签排序，不假造相似度
重要性低—照写，importance 低即可更早被压成索引（仍可召回），不需要专门丢

把"连不上模型"的处理放在库里是错误的：那是宿主应用的事（CLI 选择报错退出，桌面宠物可以选择气泡提示"我有点晕，刚才那句没记住"）。库只负责一件事——没有可靠的语义判断，就不产生记忆，像发烧的人记不住事。这样也避免了"模型时好时坏导致同一句话有时存有时不存"这种无法验收的行为。

为什么取消"importance < 0.25 就丢"：同一个句子存不存，取决于模型调用是否超时——模型坏了反而存得更多。这种"结局依赖可用性"的行为无法验收。取消之后，丢弃统一由衰减完成：低价值的记忆自然沉底，需要的记忆被复习留下，遗忘变成一种可观测的时间函数，而不是一个隐式的 if。

五、冲突与更新： embedding 粗筛 + system2 仲裁 + supersede 链

flowchart TD
    N["新记忆 mem"] --> E{"embedding 粗筛<br/>cos ≥ 0.65，取 top3（不看层级）"}
    E -->|"无候选"| SAVE["直接落库"]
    E -->|"有候选"| C["system2 四分类：<br/>补充 / 更新 / 矛盾 / 无关"]
    C -->|"无关"| SAVE
    C -->|"补充"| LINK["两条都保留，加 related 标签"]
    C -->|"更新 / 矛盾"| SUP["新记录 supersedes=旧 id<br/>旧记录转 archived（原文保留）"]
    LINK --> SAVE
    SUP --> SAVE

上一版用余弦 0.85 直接覆写 old.content，后果是"用户说偏好深色"之后改说"偏好浅色"，旧事实被永久擦掉，而矛盾仲裁无从谈起。本版：

  • 相似只用来挑候选，不用来下结论；
  • 是不是同一件事、是更新还是矛盾，由 system2 回答（一次很短的调用，输入只有新旧两条文本）；
  • 任何"取代"都留下 supersedes 链，旧记录 archived 且原文完整——任何时候都能回答"这条记忆是怎么变成现在这样的"；
  • 粗筛不按层级过滤。层级由小模型判定，同一件事两次可能被判成 semantic / identity，拿它当去重条件会让"改口"直接漏掉（实测踩过：深色→浅色被分成两层，整条替代链没触发）。层级只在反思合簇时才用。
  • 提醒不参与关系仲裁。两条提醒是两件待办，实测 0.8b 会把「提醒我体检」和「提醒我开会」判成 update，于是后者把前者归档——一条提醒被另一条吃掉。所有带 due_at / pending_due 的记忆既不作为候选，也不发起仲裁。

粗筛阈值 0.65 是实测值（qwen3-embedding:0.6b：相关 0.78~0.90、无关 0.37~0.61），换 embedding 模型后必须重标；拿不准时把粗筛放宽（宁可多问 system2 一次），不要收紧。

六、重要性评分（纯规则，只加分不丢弃）

def score_importance(turn: str, extracted: dict) -> float:
    """只回答「先想起谁」，不回答「存不存」。"""
    score = 0.0
    if has_explicit_remember_request(turn):   score += 0.5   # 用户明确说「记住」
    if extracted["layer"] == "identity":      score += 0.3
    if extracted["layer"] == "procedural":    score += 0.2
    score += 0.1 * min(len(extracted["entities"]), 3)
    if is_repeated_pattern(extracted["summary"]):  score += 0.2  # embedding 命中已有记忆
    return min(1.0, score)

is_repeated_pattern 的实现要求：用新记忆的 embedding 与候选记忆的 embedding 比较，不得在打分阶段对所有记忆重新计算向量（上一版每轮 O(N) 次 embedding，随记忆增长线性变慢）。

七、召回线

def retrieve_memories(turns: list[str]) -> list[Memory]:
    """turns 是工作记忆，本轮在最后一条。"""
    # 1. 查询表示：逐轮 embed，按轮次加权合成（越近权重越高），不做字符串拼接
    vectors = [embed(t) for t in turns]
    weights = [0.5 ** (len(turns) - 1 - i) for i in range(len(turns))]
    qvec = normalize(sum(w * v for w, v in zip(weights, vectors)))

    # 1b. 门与排序分开：只用本轮最后一句当「现在在问什么」。
    #     整段上下文混在一起会把无关旧账也顶上来（实测：连续聊过界面后问天气，
    #     仍会返回界面偏好）。纯追问（「那它呢」「继续」）没有检索内容，跳过这道门。
    focus = None if is_context_only(turns[-1]) else normalize(embed(turns[-1]))

    # 2. 候选：**全部记忆**都在候选池里，归档不等于消失
    candidates = dedup(vector_search(qvec, k=50), tag_lookup(turns))

    # 3. 精排：纯规则打分，不需要模型
    scored = []
    for mem in candidates:
        apply_decay(mem, clock.tick)                      # 惰性衰减，按经历轮次结算
        if focus and normalize_similarity(cosine(mem.embedding, focus)) < MIN_RELEVANCE:
            continue                                      # 语义上不相关：强度再高也不该被想起
        relevance = normalize_similarity(cosine(mem.embedding, qvec))
        score = (relevance * 0.40 + mem.strength * 0.25
                 + mem.importance * 0.20 + freshness(mem, clock.tick) * 0.15)
        if mem.layer == "identity":
            score = max(score, 0.5 * relevance)           # 身份层保底
        if mem.status == "archived":
            score *= 0.5                                  # 压缩态：仍能想起，只是排在清晰记忆之后
        scored.append((score, mem))

    # 4. top-N + 被动复习（想起即重新变清晰）
    results = []
    for score, mem in sorted(scored, reverse=True)[:MAX_RETURN]:
        update_strength_on_recall(mem, score)
        results.append(mem)
    return results

flowchart TD
    Q["工作记忆：本轮 + 最近几轮"] --> EW["逐轮 embedding<br/>按 0.5^k 权重合成查询向量"]
    EW --> CAN["候选 = 向量近邻 top50 + 标签匹配 → 去重"]
    CAN --> DEC["apply_decay（仅对候选，按 tick 结算）"]
    DEC --> SCOR["score = relevance×0.40 + strength×0.25<br/>+ importance×0.20 + freshness×0.15"]
    SCOR --> IDQ{"身份层？"}
    IDQ -->|"是"| FLOOR["score ≥ 0.5×relevance 保底"]
    IDQ -->|"否"| SORT["排序取 top MAX_RETURN"]
    FLOOR --> SORT
    SORT --> RV["被动复习：强度↑ 计数↑<br/>last_review_tick = 当前 tick"]
    RV --> OUT["返回记忆列表，注入本轮回复上下文"]

逐轮加权而不是拼接，是因为拼接会把"那它还有什么讲究"这类只有指代的轮次稀释掉，而权重衰减保留了"最近说的是什么"。

被动复习与复习间隔

REVIEW_INTERVALS = [1, 2, 5, 12, 30, 70, 150, 300]   # 单位：经历轮次（tick），曲线形状沿用艾宾浩斯

def update_strength_on_recall(mem: Memory, relevance: float) -> None:
    """被召回 = 一次主动复习：间隔越复习越长，强度增益越复习越小。"""
    gain = 0.12 / (1 + mem.review_count * 0.3)
    mem.strength = min(1.0, mem.strength + gain * relevance)
    mem.review_count += 1
    mem.last_review_tick = clock.tick
    mem.next_review_tick = clock.tick + REVIEW_INTERVALS[min(mem.review_count, len(REVIEW_INTERVALS) - 1)]
    mem.status = "active"

八、反思线（定时任务，允许调用模型）

def reflect_loop():
    # 一次反思 = 一次「睡眠整理」：把所有活跃记忆按当前 tick 统一结算一次，
    # 再做合簇与升级。注意 tick 不因为反思而前进——反思不是经历，只是整理。
    # 1. 睡眠整理：所有活跃记忆按当前 tick 统一结算衰减
    for mem in store.active():
        apply_decay(mem, clock.tick)
    for mem in store.find_by_status("fading"):
        if mem.strength < 0.03:
            mem.status = "archived"          # 归档，不删除

    # 2. 提醒的到期与过期（日期判断，只在这里发生，且由宿主提供 today）
    for mem in store.all():
        if mem.due_at and mem.due_at < today and mem.notified:
            mem.status = "archived"          # 方案 c：过期就归档，原文保留仍可召回
        # 没交付过的过期提醒不归档——宿主关机期间不该静默丢失

    # 3. 合簇：默认关闭（合并会改写当前摘要；先回放验证）
    #    （「用户要买蛋糕」与「用户要交房租」余弦 = 1.000），任何阈值下都会把无关记忆
    #    合成一条。换中文能力足够的嵌入模型（如 bge-m3）并重标阈值后再打开。
    if MERGE_ENABLED:
        for cluster in cluster_by_embedding(store.active(), threshold=MERGE_THRESHOLD):
            if len(cluster) < 2:
                continue
            merged = ask_system2_to_merge(cluster)   # "这些是不是同一件事？合并后怎么表述？"
            if merged:
                store.save(new_memory(merged, supersedes=[m.id for m in cluster]))
                for m in cluster:
                    m.status = "archived"            # 原文保留，链路可追溯

    # 4. 身份提炼：标签/簇出现 ≥ 3 次 → 问 system2 "这些是否构成稳定的用户画像？"
    for pattern in find_recurring_patterns(store.semantic_memories(), min_count=3):
        if not has_identity_covering(pattern):
            store.save(promote_to_identity(pattern))   # system2 输出规范表述

上一版用"同一 tag 出现 3 次"直接升级身份层，而 tag 由 0.8b 抖动生成，结果是身份层几乎永不触发、偶尔误触发。本版把"是不是稳定画像"这个语义判断交给 system2，规则只负责筛出值得问的簇（这是 embedding 和计数的正当用途）。

嵌入模型选择：nomic-embed-text 不适合中文

nomic-embed-text 实测：用户要买蛋糕 vs 用户要交房租 余弦 1.000，vs 用户要给妈妈打电话 0.987——在中文短句上几乎不区分内容，任何阈值都会把无关记忆判成同一件事。已换成 qwen3-embedding:0.6b（1024 维）：同一批短句，无关 0.37~0.61、相关 0.78~0.90，区分度正常。换模型后所有阈值（0.65 / 0.85 / 0.30 / [0.35,0.90]）都按新分布重标过。

十、延迟与并发

flowchart LR
    IN["用户一轮输入"] --> WM["写入工作记忆（快照本轮）"]
    WM --> RT["召回（embedding + 规则排序，< 50ms）"]
    RT --> REPLY["生成回复"]
    WM --> Q["编码队列"]
    Q --> ENC["异步编码：system2 抽取 + embedding + 冲突仲裁"]
    ENC --> DB["落库"]
    RF["定时反思（每日/启动后闲时）"] --> DB
  • 编码永远不在回复路径上。这是取消"长度预过滤"的前提：不为了 0.5 秒延迟而丢数据，而是把 0.5 秒移到用户读回复的那几秒里。
  • 队列必须携带本轮原文与当时的工作记忆快照，不能用"处理时的当前工作记忆"——否则异步化会让上下文错位。
  • 反思任务串行化（单实例），避免两个 worker 同时对同一簇做合并。
  • tick 在写入工作记忆时 +1，同步完成；编码失败、重试、延迟处理都不影响它。这样"经历了多少轮"与"处理了几次"解耦，重试也不会让记忆凭空老化。
  • 启动时 tick 从 meta 表恢复；库文件缺失即从 0 开始，不做任何基于墙钟的补偿。

十一、可验收的不变式

这一节是给测试用的。每一条都能写成断言，破坏其中任意一条即视为架构回退：

#不变式怎么测
I1规则不得基于长度/字数/标点做丢弃把 5 字的真偏好喂进编码线，必须产生记忆
I2skip 与 error 必须可区分：skip 是正常结论（本轮无新信息），error 是模型不可用——两者都不产生长期记忆，但 error 必须抛错给宿主stub 模型分别返回 (nil, nil) 与 (nil, err)，断言两者都不落库且返回值不同
I3已写入的 content 不被覆写构造"深色偏好 → 浅色偏好"，断言旧记录仍是深色且 status=archived、新记录 supersedes 指向它
I4模型不可用就不产生长期记忆，且与 skip 可区分关掉本地模型跑一轮 add，断言返回错误且库里一条都没多（原文只在工作记忆里）；与 worth=false 的 (nil, nil) 分开测
I5阈值不依赖未标定的向量代码里凡是用相似度的地方，embedder 必须是真嵌入实现
I6编码不出现在回复路径上注入一个 sleep 5s 的 stub 模型，断言首字延迟不受影响
I7召回结果不写回工作记忆连续两轮 ask，第二轮的工作记忆里不得出现第一轮的召回内容
I8停机不遗忘：没有新经历就没有衰减写入一条记忆后序列化整库，一个月后（墙钟前进、tick 不变）载入，断言 strength/status 完全一致
I9与墙钟无关：库内不得出现 time.Now()，时间戳只能由宿主传入把 tick 推到第 N 轮，断言结果与真实当前时间无关；grep time.Now memory/ 必须为空（测试除外）
